# 737 Mode Control Panel

| Field | Value |
|---|---|
| ID | `F-50` |
| Stage | `4` |
| Category | Aircraft-specific |
| Status | Proposed |
| Depends on | `F-20`, `F-03` |
| Competitor prevalence | Matrix count 2 of 12 representative products (`research/competitors.md`). Wider set: 2 of 13 researched companion products offer a 737-specific MCP (Air Manager, via the community Z_2D_XP instrument; Flight Deck ONE) |

## Summary

Avionix mirrors and drives the Mode Control Panel of the Zibo and LevelUp 737-800 on a phone or
tablet: the course, speed, heading, altitude and vertical speed windows, the mode buttons with
their lit annunciators, the flight director, autothrottle, bank-angle and disengage controls. It is
used from before pushback through to the approach, in place of a second monitor or hardware MCP.

## Why now

Stage 4 opens aircraft-specific coverage and the MCP is the right first panel: the research ranks
MCP/autopilot second only to the CDU in third-party tooling, ahead of the overhead and EFIS [1]. It
builds on F-20 and F-03, and forces into existence the version-pinning and missing-control
machinery that F-51 to F-54 reuse. The documented failure mode here is not missing features but
silent breakage after Zibo updates [2].

## User stories

- As a single-monitor 737 pilot, I want the MCP on my tablet so that I can set heading and altitude
  without dragging the view off the outside world.
- As a home-cockpit builder, I want a touch MCP so that I can defer buying hardware and its bridge.
- As a pilot who just updated Zibo, I want to be told which controls no longer work so that I find
  out on the ground, not on the ILS.

## Scope

### In scope

- Both course selectors; the speed window with IAS/MACH selection and the C/O change; heading;
  altitude; vertical speed.
- Mode buttons with lit state: N1, SPEED, LVL CHG, VNAV, LNAV, VOR LOC, APP, ALT HLD.
- CMD A, CMD B, CWS A, CWS B, the disengage bar, both flight director switches, the autothrottle
  arm switch, the bank-angle limit selector.
- A readout naming the detected aircraft and the add-on version the mapping was tested against.

### Out of scope (this feature)

- The EFIS panel (F-52), CDU (F-51), overhead (F-53), pedestal (F-54); ADI and HSI rendering
  (F-10, F-30).
- Any autopilot logic of Avionix's own: the app sets values and presses buttons, the aircraft
  decides.

## Functional requirements

R1. While connected to a recognised 737, every supported window shows the simulator's live value.

R2. Changing a value writes it to the simulator; the display then follows the simulator's reported
value, not the entered one.

R3. Each mode button reflects the aircraft's lit state and never latches on its own if the aircraft
does not light it. CMD A/B, CWS A/B and the disengage bar show engaged state, and a disengage is
confirmed before it is sent.

R4. The speed window shows IAS or Mach per the aircraft's current selection, with matching units.

R5. The panel states which aircraft and add-on version the mapping targets, and whether that is the
version it was tested against.

R6. When the loaded aircraft is not a recognised 737, the panel is not offered and the app names
the aircraft it did detect.

R7. When a name cannot be resolved on the loaded aircraft, that control is marked unavailable with
a plain-language reason, the rest of the panel keeps working, and the panel shows how many controls
are unavailable.

R8. On disconnection every value is marked stale within one second, no control accepts input, and
the panel says the simulator is not connected. On reconnection all names are resolved again before
any control becomes live, because simulator ids are session-scoped.

R9. A rejected write or command produces a short message naming the control and the fact that the
aircraft refused it. No raw protocol error, endpoint or payload is ever shown; tokens are never
logged.

## X-Plane Web API mapping

Reads and writes only. The ~10 Hz subscription push is adequate for MCP windows and annunciators,
which change in discrete steps [3]. Every `laminar/B738/...` name below comes from community
mirrors of Zibo's own file, not from Laminar, and is unverified.

| Purpose | DataRef / command | Type, units | Read/Write | Source |
|---|---|---|---|---|
| Course, captain | `laminar/B738/autopilot/course_pilot` | number, degrees | R/W | gist (unverified, community) [4] |
| Course, first officer | not identified; verify in DataRefs.txt | — | R/W | [5] |
| IAS/MACH selection | `laminar/B738/autopilot/mcp_dial_kts_mach` | number, selector (unverified) | R/W | [4] |
| Bank angle selector | `laminar/B738/autopilot/bank_angle_pos` | number, detent (unverified) | R/W | [4] |
| Flight director switch | `laminar/B738/autopilot/flight_director_pos` | number (unverified) | R/W | [4] |
| A/T arm switch | `laminar/B738/autopilot/autothrottle_arm_pos` | number (unverified) | R/W | [4] |
| Heading bug (generic) | `sim/cockpit2/autopilot/heading_dial_deg_mag_pilot` | float, degrees magnetic | R/W | Laminar [6] |
| Heading bug nudge | `sim/autopilot/heading_up` | command | W | `docs/xplane.md` |
| FD mode, A/T armed (generic) | `sim/cockpit2/autopilot/flight_director_mode`, `flight_director2_mode`, `autothrottle_arm`, `autothrottle_enabled` | int | R | Laminar [6], [7] |
| Speed, heading, altitude and V/S windows; N1, SPEED, LVL CHG, VNAV, LNAV, VOR LOC, APP, ALT HLD and their lights; CMD A/B, CWS A/B, disengage bar | not identified; verify in `B738_Datarefs.txt` / `B738_Commands.txt` | — | R/W | [5], [8] |

The generic `sim/cockpit2/...` names are Laminar-verified but not guaranteed to be the ones Zibo
drives; which family is authoritative per control is a verification task, not an assumption.

## Aircraft compatibility

The default Laminar 737-800 uses the standard autopilot datarefs and is served by F-20. This
feature targets Zibo and LevelUp, which publish controls under `laminar/B738/` [4]. Each supported
add-on version needs its own tested mapping; an untested version loads the newest known mapping and
says so. The Airbus equivalent is F-57.

## Competitor evidence

- The MCP is the second-most-tooled 737 panel after the CDU —
  https://forums.x-plane.org/files/file/48768-z_2d_xp-mcp-autopilot-mode-control-panel-for-zibomod/
- iPad users already run that instrument inside the Air Manager app, so a touch MCP on a tablet is
  a proven workflow — https://forums.x-plane.org/forums/topic/224735-mcp/
- Flight Deck ONE advertises real-time MCP, EFIS, autopilot and radio control across 70+ aircraft
  including Zibo — https://apps.apple.com/mx/app/flight-deck-one/id6742143273
- Zibo releases broke third-party MCP mappings at least twice: "The G-166's are no longer working
  since ZiboMod version 3.29" —

- The PMDG 737 Stream Deck profile ships 840 discrete controls with a dedicated autopilot-only
  profile, which sets the coverage expectation —
  https://flightpanels.io/en-us/products/pmdg-737-streamdeck-profiles-for-microsoft-flight-simulator

## Acceptance criteria

- [ ] On the mock server every mapped control reads, writes and reports staleness; removing one
      name yields exactly one unavailable control and a panel count, without breaking the panel.
- [ ] On a real simulator with the pinned Zibo version each window and mode button changes the
      aircraft and each annunciator follows the aircraft's own lit state.
- [ ] Disconnecting marks every value stale within one second and blocks input; a non-737 aircraft
      hides the panel and names the detected aircraft.
- [ ] No log or message contains a token, protocol code or URL.

## Risks and open questions

1. Only five Zibo MCP names are attested in the research [4]. Every other control must be read from
   the aircraft's own `B738_Datarefs.txt` / `B738_Commands.txt` and confirmed on a running sim, and
   whether each is a command or a writable dataref is unknown — that changes how a press, a hold
   and a detent behave.
2. How many add-on versions are supported at once, and whether an untested version is blocked or
   allowed with a warning, is an open product question. LevelUp is assumed to share the
   `laminar/B738/` surface; unverified.
3. Whether the aircraft reports a mode as armed as well as engaged is unknown; if not, the panel
   must not imply it does. Detent enumerations are likewise unsourced.
4. Whether a rotary driven by repeated command activation drops steps at 10 Hz needs measuring [3].
