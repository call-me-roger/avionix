# 737 / Airliner Home-Cockpit & Companion Ecosystem — Research

Scope: ProSim737, Sim-Avionics, Project Magenta, Air Manager Zibo 737 packs, Zibo-specific
tablet/remote tools (AviTab, XPlaneCDU, AirFMC, Flight Deck ONE, WebGA, Remote X-Plane Avionics,
RemoteFlight, GoFlight/GF-MCP), plus MSFS analogues (flyPadOS 3, PMDG 737 Stream Deck profiles,
MSFS Pop Out Panel Manager). Note: many `forums.x-plane.org` and some AVSIM/PMDG-forum pages
returned HTTP 403 to the fetch tool used here; where that happened, findings are based on the
search-result snippets Google/Bing indexed from those pages (quoted as such below), not a full
page fetch. This is flagged inline.

## 1. Product-by-product

### ProSim737 (ProSim-AR)
- Identity: payware avionics/systems suite for full-scale 737 home cockpits. Vendor ProSim-AR (Netherlands). Historically supported FSX/P3D and, in early versions (~X-Plane 10 era), X-Plane.
- **Current X-Plane status: NOT SUPPORTED.** The ProSim-AR FAQ states X-Plane compatibility is not provided/supported (seen via search snippet of https://wiki.prosim-ar.com/index.php/Frequently_Asked_Questions — page itself 403'd on direct fetch). Older forum threads (https://forums.x-plane.org/forums/topic/62524-prosim-737/, https://www.avsim.com/forums/topic/440880-prosim-737-latest-xplane-notes/, https://forum.prosim-ar.com/viewtopic.php?f=40&t=12986) discuss X-Plane 10-era attempts, now abandoned.
- Relevance to Avionix: ProSim737 is the market's most mature "full 737 systems + touch panel" reference (MCP, overhead, pedestal, CDU, EICAS/PFD/ND mirroring, failures) but it is FSX/P3D/MSFS-only today, so it defines the **feature bar** for a 737 companion app rather than being a direct competitor on X-Plane.

### Sim-Avionics
- Identity: payware 737 systems software, primary competitor to ProSim737, also FSX/P3D/MSFS-focused. No evidence found of active X-Plane support in the material retrieved; search results returned no dedicated Sim-Avionics + X-Plane product page. Not independently verifiable in this pass — flagged as **unconfirmed/likely no X-Plane support**.

### Project Magenta (legacy)
- Identity: legacy (2000s-era, still maintained in small updates) 737-style avionics suite: PFD/ND/MCP/CDU emulation plus MIP integration. Vendor: projectmagenta.com.
- X-Plane: Users report it still works with X-Plane 12 — a forum poster states testing "latest PM with latest version of xuipc… PM Boeing suite in xpl12 no errors, PFD ND MCP and CDU all working" (https://forums.x-plane.org/forums/topic/299080-project-magenta-cockpit-users-i-tested-latest-pm-with-latest-version-of-xuipc-dec-23-pm-boeing-suit-in-xpl12-no-errors-pfd-nd-mcp-and-cdu-all-working/ — search snippet only, page 403'd).
- Feature set (per projectmagenta.com and manual PDF http://www.projectmagenta.com/wp-content/uploads/downloads/2011/05/MagentaDoc15.pdf): Boeing-style MCP with FLCH/VNAV/LNAV/TOGA modes, Smiths/Honeywell-hybrid CDU, PFD/ND rendering, MIP integration. It runs as a **separate PC application** communicating via FSUIPC/offsets rather than the X-Plane Web API — architecturally the opposite of Avionix's browser/HTTP-WebSocket approach, and not built for Zibo-specific datarefs.
- Activity: low; mostly legacy user base, sparse recent updates (news page https://www.projectmagenta.com/news/).

### Air Manager + Zibo 737 panel packs (Sim Innovations)
- Identity: Air Manager is a general instrument/panel rendering platform (covered by another researcher); the 737-specific angle here is the **Zibo-coded panel packs**.
- Notable Zibo-specific packs found:
  - "ZIBO mod 737-800 overhead panel" — official Sim Innovations product (https://siminnovations.com/shop/zibo-mod-737-800-overhead-panel/, page 403'd on direct fetch, described via search snippet): a full interactive overhead panel synced to Zibo, sold as individually-importable `.siff` instruments so users can lay out custom panel sets per flight phase. Requires an active Air Manager license (desktop) plus the free Air Manager plugin in X-Plane; Air Manager mobile apps (iPad/Android) can then display the panel as a client.
  - "Air Manager Instruments for the Zibo 738" community pack (https://forums.x-plane.org/files/file/92297-air-manager-instruments-for-the-zibo-738/).
  - "Z_2D_XP MCP Autopilot (Mode Control Panel) for ZiboMod" — a dedicated MCP-only instrument for Air Manager (https://forums.x-plane.org/files/file/48768-z_2d_xp-mcp-autopilot-mode-control-panel-for-zibomod/ and .../for-zibomod-128/), also embeddable in the iOS Air Manager app per forum discussion of https://forums.x-plane.org/forums/topic/224735-mcp/ (search snippet: "iPad users can access the Z_2D_XP MCP Autopilot instrument embedded in the Air Manager app, with new instruments published when Air Manager for iPad is updated").
  - "Z2DXPTablet" — a Zibo community Facebook post referencing an Air Manager + Air Player Suite tablet configuration (https://www.facebook.com/zibocommunity/posts/z2dxptablet-102using-air-manager-air-player-suite-from-sim-innovations-...).
  - YouTube demo: "Air Manager | Overhead Panel | Touchscreen | Zibo 737" (https://www.youtube.com/watch?v=kosf8pngq1Q).
- Connection method: Air Manager plugin inside X-Plane reads/writes datarefs/commands; client apps (desktop, iPad, Android) render over the local network. This is the closest existing analogue to Avionix's target UX (native tablet client + LAN connection to the sim), but gated behind a paid Air Manager license and per-panel purchases, and built around Zibo-specific `.siff` files rather than a single unified app.
- Activity: actively maintained; AVSIM thread "Air manager panels for zibo question" (https://www.avsim.com/forums/topic/618847-air-manager-panels-for-zibo-question/) shows ongoing user interest as of recent posts.

### Zibo-specific remote/tablet apps (independent of Air Manager)
- **AirFMC** (iOS/Mac, $19.99, https://apps.apple.com/us/app/airfmc/id773310905): standalone CDU/FMC remote for X-Plane and MSFS 2020. Explicitly supports "Zibo mod and IXEG Classic" 737 variants plus many other types (A320/A330/A350, 757/767/777, CRJ-200). Requires a companion plugin installed in the simulator; connects via TCP/IP over LAN. Store rating 4.2★/15 reviews. Praise (quoted from App Store page): "I use this app with X-plane 11 and it works perfectly... It works flawlessly and... it's fast." Complaint: "You have to have a separate flight simulator (FMC?) for this app to work. Completely worthless without a simulator game" (i.e., a review that misunderstood it's a companion, not standalone — worth noting as an onboarding/positioning lesson).
- **XPlaneCDU** (Android, free, https://play.google.com/store/apps/details?id=net.waynepiekarski.xplanecdu): remote CDU for X-Plane 11, explicitly supporting the Zibo Boeing 738 and SSG 747, requiring the **ExtPlane v2 plugin** (not the native Web API) inside X-Plane. Search-result summaries note complaints of "very slow response when clicking CDU buttons and occasional issues with responsiveness" — could not independently confirm via direct fetch (Play Store page fetch failed/returned truncated content), so this complaint is second-hand (search-engine snippet) rather than a directly read review.
- **Flight Deck ONE** (iPad, free + IAP up to $1,299, iPadOS 18+, https://apps.apple.com/mx/app/flight-deck-one/id6742143273): broad remote-cockpit app claiming 70+ aircraft including **Zibo 737** and ToLiSS Airbuses, 120 "avionics" modules, customizable dashboards, EFB with SimBrief integration, flight logbook/black-box recorder, connects via local Wi-Fi/Ethernet (UDP) to X-Plane 11/12. Only 1 rating (5.0★) at time of research — too new/thin a review base to draw praise/complaint conclusions from; noted as an emerging direct competitor by scope (multi-aircraft tablet EFB + systems control) but its own review evidence is thin (n=1).
- **WebGA (ZOAL-WebG)** (X-Plane.org store, https://store.x-plane.org/WebGA--Turn-Your-Tablet-Into-Touchscreen-Avionics_p_2242.html; forum file page https://forums.x-plane.org/files/file/96240-webga-touchscreen-avionics-for-x-plane-12-on-your-tablet/): streams G1000/G530/GCU-style panels and custom pop-out windows to iPad/Android/browser over LAN via an in-sim companion plugin. General-aviation-focused rather than 737-specific in the material found; both pages returned 403 on direct fetch, so feature detail here is limited to search snippets.
- **Remote X-Plane Avionics** (free, browser-based, https://forums.x-plane.org/files/file/101030-remote-x-plane-avionics-a330-mcdufcuefis-737-cdu-for-tablet-browser/): runs stock A330 MCDU/FCU/EFIS and the **stock (non-Zibo) 737-800's CDU** on any browser device via X-Plane's built-in Web API — no plugin required. Search summary notes "737-800 CDU support is still initial support." This is notable as the one tool in this survey confirmed to use the same native X-Plane 12 Web API mechanism Avionix will use, rather than FlyWithLua/ExtPlane/UDP bridges. Install-to-homescreen PWA-style flow for iPad noted (Safari "Add to Home Screen").
- **RemoteFlight / RemoteFlight COCKPIT HD** (iOS, https://www.remoteflight.net/, App Store https://apps.apple.com/us/app/remoteflight-cockpit-hd/id541400383): general FSX/P3D/MSFS/X-Plane 9-12 gauge-mirroring app (basic 6-instrument panel: altimeter, AI, VSI, ASI, turn/slip, DG), lightweight local server, bidirectional sync. Not 737/Zibo-specific. Mixed lag feedback per search snippets: one reviewer "There is no lag whatsoever," another "The HSI lags slightly but isn't really noticeable... under normal circumstances." AVSIM review page (https://www.avsim.com/home/reviews/remoteflight-–-flight-simulator-gauges-for-apple-devices-r1141/) returned 403 on direct fetch — could not verify beyond search snippet.
- **GoFlight GF-MCP Pro + GF-EFIS + GF-166** (hardware, ~$519 per search snippet, software-bridged via GoFlight Interface Tool "GIT"): not a tablet app but the most-discussed **hardware** MCP/EFIS for Zibo, included because forum threads about it reveal the community's dataref-breakage pain point directly. Threads: https://forums.x-plane.org/forums/topic/343245-zibo-mod-gf-mcp-pro, https://forums.x-plane.org/index.php?%2Fforums%2Ftopic%2F236794-gf-mcp-pro-and-gf-efis-in-zibo-737%2F=, https://www.pollypotsoftware.org.uk/vanillaforums/discussion/655/zibos-boeing-b738-800-mcp-pro-efis-2xgf166-lgt-ii-requires-git-1-8-2-0-for-x-plane (this last one fetched directly and successfully).

### MSFS analogues (set 737/A320 user expectations, not X-Plane products)
- **FlyByWire flyPadOS 3** (A32NX/A380X EFB, free, https://docs.flybywiresim.com/aircraft/common/flypados3/, announcement https://flybywiresim.com/notams/flypados3/): in-sim EFB with OFP/SimBrief import, VATSIM/IVAO integration, pushback with turn-radius overlay, performance calculators, "Smart" interactive checklists, simulated battery. Fetched docs show **no tablet/mobile/second-device access** — it is a single in-VC panel, and a GitHub issue explicitly requests this: "flyPad Web Server" (https://github.com/flybywiresim/aircraft/issues/6978) — i.e., FlyByWire's own users are asking for exactly the kind of external-device access Avionix provides natively. Known issues doc (https://docs.flybywiresim.com/aircraft/support/known-issues/known-issues-common/) lists: EFB losing mouse-cursor focus when tabbing away, GSX sync bugs on fuel/boarding buttons, ground-services state getting out of sync with the aircraft.
- **PMDG 737 Stream Deck profiles (Flight Panels / "Flight Panels" Gen 2)** (https://fselite.net/content/flight-panels-updates-pmdg-737-stream-deck-profile/, https://flightpanels.io/en-us/products/pmdg-737-streamdeck-profiles-for-microsoft-flight-simulator, £25 GBP, free update for existing owners): 840 individual controls across 33 pages (up from 312/12 in Gen 1) — cockpit + cabin controls, full MCDU with keyboard/numpad, audio control panel, dedicated AP-only profile for Stream Deck Plus. Alternate community options exist using the "PilotsDeck" plugin. This shows the level of **granular control-surface coverage** (840 discrete controls) that power users expect once a 737 add-on is popular — a bar Avionix's panel coverage should be measured against, panel-by-panel.
- **MSFS Pop Out Panel Manager / Pop Out Panel Manager 2024** (free, GitHub https://github.com/hawkeye-stan/msfs-popout-panel-manager, flightsim.to https://flightsim.to/addon/85158/msfs-popout-panel-manager-2024): automates popping cockpit panels into separate always-positioned windows for use on a second monitor/tablet (via Spacedesk-style remote display), adds touch support MSFS lacks natively, HUD bar with stopwatch/sim-rate, virtual numpad for touch. README explicitly supports PMDG 737 workflows. Known conflicts: breaks if flight-hardware permanently binds the master battery switch; conflicts with window-management tools like Sizer/PowerToys. This is the clearest MSFS-side proof that **users will build/adopt whole utilities just to get pop-outs onto a tablet**, validating Avionix's premise that a purpose-built companion beats ad hoc pop-out plumbing.
- "Flow Pro": no results found in this research pass; likely refers to a Stream Deck/macro tool but could not be verified — **not confirmed**.

## 2. What 737/Zibo users PRAISE (5+, sourced)

1. Air Manager's Zibo overhead panel is valued for its granular, per-instrument modularity — users can assemble only the panels they want per flight phase rather than one fixed layout (https://siminnovations.com/shop/zibo-mod-737-800-overhead-panel/, product description language, search-snippet-derived since page 403'd on direct fetch).
2. AirFMC users report it "works flawlessly" and is fast for remote CDU control over Wi-Fi: "I use this app with X-plane 11 and it works perfectly... it's fast" (App Store review, https://apps.apple.com/us/app/airfmc/id773310905).
3. RemoteFlight users report effectively no perceptible lag for basic flight instruments in normal use: "There is no lag whatsoever" (search-indexed App Store review, https://apps.apple.com/us/app/remoteflight-cockpit-hd/id541400383).
4. FlyByWire's flyPadOS 3 pushback-with-turn-radius overlay and interactive "Smart Checklists" are highlighted by FlyByWire itself as headline UX wins for the update (https://flybywiresim.com/notams/flypados3/) — evidence of what an EFB-style checklist/pushback feature is expected to look like by A320/737-adjacent users.
5. Once GoFlight GF-MCP Pro hardware profiles are correctly matched to a Zibo version, users are enthusiastic: "EUREKA!! all modules are now working properly. I am a very happy camper" (https://www.pollypotsoftware.org.uk/vanillaforums/discussion/655/zibos-boeing-b738-800-mcp-pro-efis-2xgf166-lgt-ii-requires-git-1-8-2-0-for-x-plane) — the praise is really relief that a fragile integration finally works, which is itself a signal (see complaints).
6. Flight Deck ONE's single rating is a 5.0★ (https://apps.apple.com/mx/app/flight-deck-one/id6742143273) — thin evidence, noted as such, but the described breadth (70+ aircraft, 120 avionics modules, EFB+logbook+SimBrief in one app) matches what users elsewhere ask for in a "one app to rule them all" companion.

## 3. What 737/Zibo users COMPLAIN about (5+, sourced)

1. **Dataref/version breakage after Zibo updates.** GoFlight/GIT profiles broke when Zibo changed the heading-dial dataref in a point release, and again after Zibo 3.29: "The G-166's are no longer working since ZiboMod version 3.29" (https://www.pollypotsoftware.org.uk/vanillaforums/discussion/655/zibos-boeing-b738-800-mcp-pro-efis-2xgf166-lgt-ii-requires-git-1-8-2-0-for-x-plane). Dedicated forum threads exist specifically to track dataref churn, e.g. "The problem of dataref in Zibo 737" (https://forums.x-plane.org/forums/topic/316935-the-problem-of-dataref-in-zibo-737/) and "ZiboMod Datarefs questions and requests. New Datarefs availability requested" (https://forums.x-plane.org/forums/topic/184978-zibomod-datarefs-questions-and-requests-new-datarefs-availability-requested/) — both seen via search snippets, direct fetch 403'd.
2. **Setup complexity for hardware/software bridges.** GF-MCP Pro users had to hand-copy Commands.txt/Datarefs.txt files into the aircraft directory before the GoFlight Interface Tool would recognize Zibo, and reported "Some controls failed to load" errors and empty command/dataref files causing GF-166 display failures (https://www.pollypotsoftware.org.uk/vanillaforums/discussion/655/...). One user in the same thread asked plainly: "how I should import this settings in GIT?" — evidence of steep first-run friction.
3. **Resource/performance overhead of third-party interface layers.** A user described struggling for "years" to get GF-MCP Pro working with Zibo across "various free and payware interfaces," specifically calling PollyPot's interface "extremely resource hungry" (search snippet from https://forums.x-plane.org/forums/topic/343245-zibo-mod-gf-mcp-pro and related PollyPot discussion threads).
4. **Hardware reliability/reconnection friction.** GF-166 radio modules reportedly required unplugging/replugging every time X-Plane loads, and froze mid-flight in at least one report (search snippet, https://forums.x-plane.org/forums/topic/343245-zibo-mod-gf-mcp-pro).
5. **Sluggish touch response in a remote CDU app.** XPlaneCDU (Android) users reported "very slow response when clicking CDU buttons and occasional issues with responsiveness" (search-engine snippet referencing https://play.google.com/store/apps/details?id=net.waynepiekarski.xplanecdu — the Play Store page itself could not be fully fetched, so this is second-hand and flagged as lower-confidence).
6. **Non-standalone positioning confusion.** An AirFMC reviewer complained "You have to have a separate flight simulator (FMC?) for this app to work. Completely worthless without a simulator game" (https://apps.apple.com/us/app/airfmc/id773310905) — a companion app that doesn't make its "you need X-Plane running" dependency obvious in its store listing collects 1-star confusion reviews.
7. **No official multi-device/mobile EFB even on the most polished competing platform.** FlyByWire's flyPadOS 3 has no tablet/second-device mode at all, and their own community filed a feature request for it — "flyPad Web Server" (https://github.com/flybywiresim/aircraft/issues/6978) — confirming this is a felt gap even for A320 users on the best-regarded free EFB in the hobby.
8. **X-Plane compatibility abandonment by top-tier commercial suites.** ProSim-AR's own FAQ states X-Plane is not supported/not something they help with (https://wiki.prosim-ar.com/index.php/Frequently_Asked_Questions, search snippet), which repeatedly disappoints X-Plane-based 737 home-cockpit builders who ask about it (https://forums.x-plane.org/forums/topic/62524-prosim-737/, https://questions.x-plane.com/26464/xplane-with-prosima320 for the A320 equivalent question pattern).

## 4. Panels/functions 737 tablet users most want (prioritized, most → least requested)

Ranking is inferred from (a) which panels have the most dedicated third-party tools/threads found, (b) explicit feature requests found in sourced threads, and (c) coverage depth of the most mature MSFS analogue (PMDG Stream Deck Gen 2, 840 controls/33 pages). Marked [inference] where based on triangulation rather than a single explicit "please add X" quote.

1. **CDU/FMC remote control** — by far the most third-party activity: AirFMC, XPlaneCDU, Remote X-Plane Avionics, Flight Deck ONE, plus multiple forum threads specifically about getting the CDU onto an iPad (https://forums.x-plane.org/forums/topic/118712-remote-cdu-on-ipad-safari-browser/, https://forum.pmdg.com/forum/main-forum/general-discussion-news-and-announcements/329858-cdu-on-an-ipad, https://forum.pmdg.com/forum/main-forum/pmdg-737-for-msfs/general-discussion-no-support/189667-cdu-to-your-tablet).
2. **MCP/autopilot panel** — second-most product activity: Z_2D_XP MCP Autopilot for Air Manager, GF-MCP Pro hardware + years of bridging effort, multiple dedicated forum threads ("Best MCP and EFIS hardware panel," "MCP," "Zibo mod + GF MCP Pro").
3. **Overhead panel** — dedicated Sim Innovations product + community Air Manager packs + multiple forum threads (CP Flight, FlightsimPM) asking specifically how to get the overhead onto a second touchscreen ("737 Overhead in the Zibo Mod" thread asks about displaying overhead "on a separate touchscreen," https://forums.x-plane.org/forums/topic/187475-737-overhead-in-the-zibo-mod/).
4. **EFIS control panel (PFD/ND mode & range selectors)** — consistently bundled with MCP requests (GF-EFIS, Air Manager EFIS packs) rather than requested standalone; ranked below overhead because it's almost always an add-on to an MCP purchase, not a first purchase.
5. **EFB-style functions (performance calc, checklists, weight & balance)** — Zibo already ships a built-in tablet/EFB with takeoff/landing performance calculators and failure injection (per Navigraph's blog on Zibo, https://navigraph.com/blog/zibo-737, and a dedicated thread "Takeoff and Landing Performance Calculator via Zibo Tablet," https://forums.x-plane.org/forums/topic/198742-takeoff-and-landing-performance-calculator-via-zibo-tablet/) — demand here is more about **getting the existing in-sim tablet onto a real external tablet** than about building new EFB features from scratch. [inference: this reduces novelty value unless Avionix also improves on Zibo's native tablet UX/ergonomics]
6. **Pedestal (radios/transponder/audio panel)** — present in Air Manager packs and PMDG Stream Deck's "audio control panel," but fewer dedicated single-purpose apps found than for CDU/MCP; [inference] likely because radios are simpler controls that get bundled into general remote-panel apps (Flight Deck ONE, RemoteFlight) rather than warranting their own product.
7. **PFD/ND/EICAS full display mirroring** — supported by Project Magenta (legacy) and general tools (Air Manager, RemoteFlight base gauges) but not a major standalone-app category on its own for Zibo specifically — most Zibo users rely on in-sim popouts/second monitor rather than a tablet render of primary flight displays. [inference]
8. **Fire/overhead emergency panel, failures management** — least third-party tooling found; largely handled inside Zibo's own tablet (failure injection) rather than by external apps.

## 5. Technical note: Zibo datarefs/commands and community documentation

- **Prefix convention:** third-party tools uniformly target the `laminar/B738/...` dataref namespace (Zibo publishes its custom dataref/command set under the `laminar/B738/` prefix rather than a Zibo-branded prefix, since Zibo is licensed to distribute under Laminar's B737 default-aircraft namespace). Examples seen directly in code: `laminar/B738/autobrake/autobrake_pos`, `laminar/B738/toggle_switch/irs_left`, `laminar/B738/engine/mixture_ratio1`, `laminar/B738/annunciator/parking_brake`, `laminar/B738/systems/lowerDU_page`, `laminar/B738/tab/cg_pos` (from a live feature-request thread asking that a CDU LSK update this exact dataref: https://forums.x-plane.org/forums/topic/346056-feature-request-takeoff-req-lsk3-cg-should-update-laminarb738tabcg_pos-dataref).
- **Where community dataref lists live:**
  - `B738_Datarefs.txt`, shipped inside the Zibo aircraft folder itself (referenced by multiple integration guides, e.g. https://www.mobiflight.com/forum/topic/5648.html and https://www.cockpitbuilders.com/index.php?topic=7469.0) — this is the closest thing to an "official" list, distributed with the mod rather than published as a standalone spec page.
  - Community-maintained mirrors/subsets on GitHub: https://github.com/Najsr/X-Plane-Voice-Control/blob/master/B738_Datarefs.txt (a plain-text dump used for a voice-control project), and working Lua examples in https://github.com/daniol/xsaitekpanels-zibo (switchpanel.lua, multipanel.lua) and https://github.com/teamsuperpanda/zibovirtualco.
  - Forum-based Q&A threads function as a de facto changelog/FAQ for datarefs: https://forums.x-plane.org/forums/topic/139936-zibo-737-mod-datarefs-inquiry/, https://forums.x-plane.org/forums/topic/289572-zibo-737-annunciators-datarefs/, https://forums.x-plane.org/forums/topic/184978-zibomod-datarefs-questions-and-requests-new-datarefs-availability-requested/, https://forums.x-plane.org/forums/topic/339977-datarefs-needed/.
- **Rate of change:** based on the GF-MCP Pro thread history, datarefs/commands have changed at least twice across tracked Zibo point releases (a heading-dial rename at "3.10b," and GF-166 breakage at "3.29"), each requiring the third-party tool's profile/mapping to be republished (https://www.pollypotsoftware.org.uk/vanillaforums/discussion/655/...). Combined with the existence of a standing "Datarefs needed" request thread (2024-era, https://forums.x-plane.org/forums/topic/339977-datarefs-needed/) this indicates the dataref surface is **actively extended, and periodically renamed/restructured**, not a frozen spec — Avionix should build a versioned/tested dataref-mapping layer rather than hardcoding names, and watch Zibo release notes.
- **Plugin dependency vs. native Web API:** most mature Zibo tools do **not** use the X-Plane 12 Web API (which didn't exist for most of their lifetime); they rely instead on either (a) an in-sim plugin bridge — Air Manager's own plugin, the FlyWithLua scripts underlying several panel packs, or ExtPlane v2 (required explicitly by XPlaneCDU) — or (b) UDP/FSUIPC-style offset access (Project Magenta). **Remote X-Plane Avionics** is the one tool found in this research that explicitly runs off X-Plane 12's native Web API with "no X-Plane plugin required" (https://forums.x-plane.org/files/file/101030-remote-x-plane-avionics-a330-mcdufcuefis-737-cdu-for-tablet-browser/), making it the closest architectural precedent for Avionix. This split matters for Avionix's positioning: the Web-API-native approach avoids the plugin-install friction and FlyWithLua/ExtPlane version-pinning that shows up repeatedly in the complaint threads above.

## 6. Notable UX patterns worth copying or avoiding

1. **Copy:** Air Manager's per-instrument modularity (import only the panels/instruments you want, arrange by flight phase) — lets a single 737 pack serve very different physical/tablet layouts without forcing one fixed skin (https://siminnovations.com/shop/zibo-mod-737-800-overhead-panel/).
2. **Copy:** flyPadOS 3's pushback overlay with live turn-radius/projected path, and interactive "Smart Checklists" tied to aircraft state — concrete, well-received EFB patterns worth replicating for the 737 EFB pages (https://flybywiresim.com/notams/flypados3/).
3. **Avoid:** shipping a companion app whose "you must have the simulator running and networked" dependency isn't obvious up front — it produces confused 1-star reviews from users who expected a standalone product (AirFMC example, https://apps.apple.com/us/app/airfmc/id773310905).
4. **Avoid:** brittle hand-authored dataref/command mapping files that must be manually copied into place and silently break on every Zibo point release with no compatibility shim or version check — the single biggest source of documented user pain in this whole category (GF-MCP Pro/GIT thread, https://www.pollypotsoftware.org.uk/vanillaforums/discussion/655/...). Build an explicit dataref-version compatibility layer and surface a clear in-app error when a mapped dataref is missing/renamed, rather than failing silently.
5. **Copy (validated gap):** the fact that even FlyByWire's own users are filing feature requests for exactly "run the EFB on another device" (https://github.com/flybywiresim/aircraft/issues/6978) confirms real demand for Avionix's core premise — a companion app is filling a gap the add-on developers themselves haven't closed, even in the best-supported non-X-Plane analogue.
